ZONGZI AI WORLD · 深度编译

来源：Lightcone（Y Combinator）｜ 嘉宾：Jeffrey Morgan，Ollama 联合创始人兼 CEO ｜ 2026 年 9 月

先看三个数字。900 万开发者、178,000 颗 GitHub star、85% 的《财富》500 强公司在用——这是 Ollama 今天的样子。而它的联合创始人兼 CEO Jeffrey Morgan，是在 YC 的播客《Lightcone》里承认的：他们直到今年才开始真正赚钱。

这期节目里最值钱的东西不是某个参数，而是一条曲线：Ollama 云上"每个开发者每周消耗的 token 量"，从今年年初到节目录制时涨了 150 倍。注意，这是人均，不是总量。曲线有两个拐点：年初的编程 agent（coding agent），和 4 月的 OpenClaw。

Morgan 给了一个可能比任何 benchmark 都更重要的判断：在企业里，未来 80%–90% 的 token 会走开源模型，但只会花掉 10%–20% 的钱。

以下是这期对话的编译。

主要观点

  • 开源模型在企业里正从"省钱选项"变成默认选项，驱动力是编程 agent 带来的人均 token 爆炸。
  • 企业要的不只是便宜，而是掌控：成本只是入场券，把模型按自己的业务定制才是北极星。
  • 发布日（day zero）是一门系统工程：模型、推理引擎、harness、硬件供应商全都要在最后 24 小时里对齐，Morgan 称之为"消防演习"。
  • 新的稀缺不在 token 之下，而在token 之上：知识、协调、执行这三层，是下一批公司的机会。
  • 稳态是"九成 token 走开源，只占一两成预算"，最难的任务仍然留给前沿实验室。
  • 两年"荒野"换来两周上线：Ollama 真正的转折点，是把桌面端的运行体验做到零摩擦。
  • 几条基础设施时代的老规则失效了：模型的不确定性是特性不是 bug，"只是上层"也不再脆弱。

150 倍：两个拐点，和一个被忽略的指标

Ollama 最初是"在 MacBook 上跑开源模型"的工具，支持英伟达、AMD、Intel 的硬件。今年它上线了 Ollama 云，于是 Morgan 手里有了一份别人拿不到的数据：谁在真的用模型、用多少。

他看到的第一件事是，云上的 token 现在主要来自中国 origin 的模型，但调用者遍布全球——美国是最大的来源之一，德国也是大户。

第二件事是需求结构的突变。年初第一波上涨来自编程 agent：Kimi、GLM、MiniMax 这批模型终于让开源模型能撑起编程 agent。第二波发生在 4 月，OpenClaw 起飞，接着是 Hermes 这类 agent 项目——从"只有开发者"变成"任何人都能把一个难题丢给模型，让它自己跑完"。

这里面藏着两个被忽略的技术变化：一个是模型的上下文窗口从 128K 抬到 100 万以上；另一个是任务的时长被拉长了。Morgan 说，agent 在解决一个任务时要判断用什么工具、去取什么数据，这本身就是海量 token。

于是有了那个数字：人均消耗先是大约 5 倍的跳升，整体上云的用量是 10–20 倍级别，而云端整体比年初涨了 150 倍。

他还顺手纠正了一个行业惯性：2024、2025 年，被大规模服务的开源模型大多是微调过的定制模型（比如 Cursor 那套做法）；而"开箱即用的开源模型直接被大规模服务"，是今年才真正开始的。

不是为了省钱，是为了掌控

主持人问得直接：企业是不是只图便宜？

Morgan 的回答很有层次：成本是开源模型能解决的最大痛点，但不是终点。省下来的钱只是让企业有余力去做下一件事——把模型按自己的业务定制化，"这才是他们真正的北极星"。

他给了一个具体案例：据 The Information 的报道，AT&T 已经把 40% 的 token 消耗迁移到了开源模型上，目前以美国和欧洲的模型为主，同时也在评估中国模型。

"从我们的经验看，无论客户在欧洲还是美国，只要能解决安全问题，采用中国 origin 的模型实验室，基本上完全在桌面上。"

真正的拦路虎不是技术，是安全与合规。他提到 GLM 5.3 发布时，它在网络安全方向的能力"极其惊人"——这反而是创业公司的机会窗口：安全与治理会变成一门独立的生意。

这里还有一个反直觉的用例。主持人问：哪里能用开源模型取得"碾压式"的优势？答案是安全测试。你让闭源的前沿模型去给自家产品做渗透测试，它大概率会拒绝；而 Hugging Face 上那些专门做安全研究的模型，可以放手去干。

Morgan 对"木马"式的担忧也给了现实的回答：开源模型的供应链风险，对《财富》500 强的安全团队并不新鲜——一个现代应用有上千个依赖，只要一个出问题就能出大事，这是他们做了几十年的事。模型只是更不透明，但它同样是确定性的；只要在上线前做足够的安全筛查，客户的反馈是"基本上可以解决"。

发布日是一场消防演习

主持人注意到一个细节：作为模型的关键分发渠道，Ollama 往往会在模型公开发布前就拿到通知，甚至提前拿到模型。Morgan 承认了，并把这套流程叫做"day zero playbook"：

1. 让模型在你的推理引擎里被支持——这常常要花好几周，要保证它快、准、和参考实现对齐；

2. 找到合适的 harness（承载 agent 循环的外壳），让开发者真的能用上新能力；

3. 把硬件和供应商对齐——英伟达、Apple silicon 这类栈都要跑得快，"模型很强但很慢，体验就是糟糕"。

但现实是，大部分事情都挤在发布前的最后 24 小时里完成。他举了个例子：录制当天早上，DeepSeek 发布了他们的第一个多模态大模型，同时更新了自己的 DeepSeek harness，才让这个能力真正可用。

主持人用了一个类比：这像操作系统——你要适配所有驱动、所有硬件，还要保证上层应用跑得顺。Morgan 接住了这个类比：他们要做的，是一个能"把任意 harness 匹配到任意模型"的公共运行时；而在他看来，这是一个"组合爆炸"级别的难题。

他还透露了团队构成的秘密：他们大多不是 AI 研究员，而是来自 VMware 和 Docker。那些经典的算力问题，正在推理这一层上重演。

五层蛋糕之外，新的稀缺在 token 之上

聊到英伟达那套"五层蛋糕"（应用、模型、基础设施与推理、芯片、能源），Morgan 说了一句值得做笔记的话：开源模型这一侧的层数可能更多。

因为在"模型"这一层里，除了权重，还有大量编排组件；在模型和应用之间，还有一整个开发者 API 层，今天被折叠在蛋糕里看不见。

主持人追问：这些隐藏层会不会被拆出来，变成独立的公司？Morgan 的答案是"绝对会"，并引用了 Anthropic 平台团队的一个分类：

  • 知识（knowledge）：怎么把公司的数据和上下文接进模型；
  • 协调（coordination）：一个请求会派生出多个子 agent，有的在云上、有的在本地，谁来调度；
  • 执行（execution）：也就是沙箱，而且越来越多 agent 跑到云上，算力问题巨大。

他的推论是历史性的：云计算时代的经验是，开发者最终会选择每个环节的最佳单品，而不是接受一个捆在一起的套餐（当年的 Heroku、Google App Engine 就是把所有东西打包卖）。开源模型这一侧，"token 正在变得充裕，新的稀缺是 token 之上的东西"——而一个独立开发者不可能自己造完所有层。

也有东西不会沉到模型里去。Morgan 说，凡是有状态的问题（存储、记忆）都很难下沉，因为模型再新，训练也不是实时的；凭据、安全、合规工具同理。他的判断是：存储是一个巨大的问题空间，他不认为它会沉进模型层。

稳态：九成 token，一两成预算

全场最值得抄下来的一段，是他对终局的描述。

Morgan 的判断是：在一家企业里，绝大多数 token（他给的数字是 80%–90%）会走开源模型，但这不代表 89% 的预算也走开源——恰恰相反，开源社区正在把成本压下来，所以你可能只为开源模型付 10%–20% 的钱。

"你不会再想着从团队手里收回 token 权限，而是给他们更多。"

真正最难的任务，仍然留给拥有最强研究员的前沿实验室；中间的大片地带，是闭源和开源配合完成的。

主持人用了一个精妙的类比：这就像律所——合伙人接活，然后把活分给一大群 associate。开源和闭源的关系，也是这个结构。Morgan 顺着补了另一个类比：就像云计算时代，客户会用 AWS 自研的 DynamoDB，也会同时用开源的 PostgreSQL。

他还提到，已经有项目在做这种混合调度，效果不错。

本地模型会回来

Ollama 起家于本地。Morgan 发现，今天最吃力、最需要大模型的活——编程 agent——在云上；但本地不会消失，而是会回来。

原因在硬件。他提到，这一代硬件在 200 亿到 400 亿参数这一档表现极好，有时能到 1280 亿参数。他甚至引用了一个让人吃惊的对比：Qwen 3.8 38B 在编程上已经可以和一档前沿闭源模型掰手腕，而它跑在你买得到的、内存倒数第二小的那台 MacBook 上。

这意味着一种混合执行：简单、直接的活放在本地跑（低延迟、按 token 算几乎免费，因为硬件本来就是企业要买的）；难的活交给云上的大模型，中间由一个路由器（router）来判断。

他还说了一个有意思的分野：云上跑编程 agent 的，今天绝大多数是中国模型；本地则是美国、欧洲、中国模型的混合。他期待美国实验室补上大模型这一课——英伟达的 Neotron Ultra 被他视为第一波信号。

硬件这边，他提到了两件具体的事：英伟达的 DGX Spark（128GB 统一内存，覆盖 20B–120B 模型区间），以及带 GB300 的 DGX Station；这些设备还能用高速网络堆叠起来，在桌上拼出一个迷你数据中心，跑 400B 级别的模型。他甚至提到一个被低估的现实：很多银行和工业企业，每一张工程师的桌子上早就有一块英伟达工作站 GPU，数量以万计。

至于 GPU 市场本身，他的描述是价格变化极快、供需波动极大，创业公司想拿到最新的 B200、B300"非常难"——这也正是 OpenRouter、Ollama、OpenCode 这类中间层的价值：开发者不必自己去谈一张 B200 的价格和 24 个月预测。

给没钱创业者的账：Flash 模型与"无限 token"

主持人问了一个很实际的问题：如果现在创业、钱不多，怎么用有限的预算榨出最多的 token？

Morgan 的答案是一类新模型：以 DeepSeek Flash 为代表的"超低价"档位。他特别强调了一个很少被讨论的指标——不只是每 token 成本低，而是每任务成本低。

他认为这类"够用、极快、极便宜"的 flash 模型，会先把我们带回那个"无限 token"的年代：就像当年用 ChatGPT，你从不计算自己用了多少 token，只是每天用。而这一次，是把整条工作流交给它跑。

数据也支持他：Ollama 云上增长最快的正是 DeepSeek 这一支，主要由 Flash 版本拉动。

这套逻辑对创业者的启发是：当每个任务的成本足够低，你就能把"编排"当作产品——把多个便宜的模型串起来，去解决原本只有大模型才能解决的问题。他提到，开源模型和前沿闭源模型之间的差距，现在"可能不到 3 个月"；而当差距变成"正面竞争"而不是"代差"，商业机会就从"用最强的模型"转向"用最划算的组合"。

从 Docker 到 Ollama：两年荒野，两周上线

节目的后半段，Morgan 复盘了 Ollama 的来路，这段对做产品的人可能比技术判断更有用。

他和联合创始人 Michael 是滑铁卢大学的室友，一起做过一家公司，很早就被 Docker 收购，两人在 Docker 期间做了 Docker Desktop。2021 年他们申请 YC 时，写的方向是"Kubernetes 版的 Kitematic / Docker Desktop"——一个给 Kubernetes 做桌面体验的产品。

那之后是两年找不到北极星的荒野：从 Kubernetes 的安全，到桌面端开发者安全（"这个转向我们从来没公开讲过"），到 2022 年拿 Benchmark 的 A 轮（投资人是 Docker A 轮的投资人 Peter），再到 2023 年 7 月 Ollama 上线。

真正的转折点发生在一间会议室里。他们坐在多伦多（当时团队分散在多伦多和帕洛阿尔托），说："把一切推倒重来——如果今天我们才加入，我们会做什么？"

结论有两个方向：一个是做"LLM 版的 Segment"（今天我们会叫它 router），另一个是发挥他们真正的肌肉——让开源模型跑起来。于是他们给自己两周时间，做出第一个版本；就在两周快结束时，Llama 2 发布，他们说：发。

"从想法到上线只用了两周，然后我们就有了比之前所有产品都多的用户。在那之前，是两年把客户、把产品都想得太多，却什么都没发出去。"

接下来是那个著名的数字：GitHub star 涨到 10 万的速度比 Docker 和 Kubernetes 都快。他是从 Reddit 的本地 LLM 版块知道自己的产品火了——而主持人补了一刀：从"Reddit 上的怪人"到 85% 的《财富》500 强，只用了大约两年，而 PC 走完同样的路用了十年。

为什么企业来得这么快？Morgan 的解释值得所有做开发者产品的人记住：开源模型免费起步、能在任何地方跑，于是《财富》500 强里的一个 IT 开发者不需要向任何人申请权限就能用。"对业余爱好者友好的东西，非常快地就变成了对企业开发者友好的东西。"加上大模型本身是无状态的，迁移成本比数据库时代低得多。

至于"两年不赚钱"这件事，他说得比大多数人诚实：Ollama 的开源版本从一开始就是一个隐私优先的 AI 产品，但他们判断真正的变现窗口还没到——要等到"最大的 AI 消耗场景"和"开源模型的能力"这两件事撞在一起，那发生在今年的编程 agent 上。他说他们从 Docker 身上学到两件事：一是不能养出一种不把变现当优先级的文化；二是最大的风险是把用户当成"互联网上的一坨"。

"我们真正后悔的是，过去几年没有更多地去找用户聊天——他们在做什么、半年后想做什么。"

几条在 AI 时代失效的老规则

节目最后，Morgan 列了几条从基础设施时代带过来、却在 AI 时代不再成立的规则，这几条对今天的创业者尤其适用：

1. "只是上面一层"不再脆弱。在平台即服务（PaaS）时代，架在别人之上是危险位置；但在 AI 世界里，往上走反而可能更好，因为你离客户更近。

2. 模型的不完美是特性，不是 bug。系统世界要求一切按设计精确运行，而大模型天然不确定——你得接受它。

3. 有些岗位不再需要那么多人。更尖锐的问题是："你怎么构建一个没有任何工程师知道全部代码如何工作的服务？"——这在今天是常态。

他还提醒了一件事：最好在创业前，至少待过一个真正做出产品市场契合（PMF）的团队。哪怕只有三个月，"你会知道什么叫做'好'——包括缺陷库长什么样、怎么发版、质量的门槛在哪里"。见过一次，成功率会被放大。

结语：三句可以带走的话

抛开所有数字，这期对话留下的可落地判断其实只有三句：

1. 别再只算模型单价，要算"每个任务的成本"。决定 AI 能不能被大规模使用的，不是每百万 token 多少钱，而是一个任务跑完要多少钱。

2. 当 token 变成商品，值钱的是 token 之上那一层。知识、协调、执行——把碎片化的模型、推理服务、harness 拼成"就是能用"的体验，本身就是一门生意。

3. 企业在开源与闭源之间的选择，最终是可控性的选择。省钱只是理由之一，能把模型按自己的业务定制、能把安全与合规握在手里，才是真正的动因。
