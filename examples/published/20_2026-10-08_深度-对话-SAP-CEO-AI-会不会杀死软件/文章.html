2026 年 9 月底，纽约证券交易所里，SAP CEO Christian Klein 和 Big Technology Podcast 的主持人 Alex Kantrowitz 聊了将近一个小时。SAP 的股价今年先跌掉 21%，又在最近两个月涨回 43%。过去一年，整个软件行业都在回答同一个问题：AI 会不会把 SaaS 一起吃掉。

Klein 的答案可以拆成三道坎，外加一个时间表。财务关账这种要 100% 准确率的活，他说现在是几个月的尺度，不是几年。他也承认，SAP 已经开始给员工设 token（词元，模型的计费单位）限额。

下面是按原话顺序编译的对话，删掉寒暄，数字和判断保留原样。

「AI 已经懂业务了，可是审计师不会接受 93% 的准确率。」

企业 AI 卡在三道坎上

Alex： 你和我最大的区别是，我聊 AI 不用为它做任何决策，你得先判断它往哪走，再拿它规划公司。如果 AI 现在停下来，是一套决策；它再冲一冲然后撞墙，是另一套；递归自我改进，又是第三套。你说说看。

Christian： 我跟员工讲的时候会放一座山。我们先爬了云这座山，现在要爬 AI 这座山，路上一定有障碍。生成式 AI 刚火的时候大家都在试模型，现在客户会问：价值在哪？为什么 AI 能读非结构化文档、能总结邮件，一碰到业务就有准确率上限？

Christian： 这是第一道坎，准确率。第二道坎是数据，你的数据放在哪、质量够不够。第三道坎全世界都在吵，要不要监管、要不要治理。我们跑的是世界上最关键的一批业务系统，治理这一环绕不开。

Alex： 但这就是核心问题。AI 现在理解结构化数据的能力还不行，而你的工作有很大一部分，就是在判断它什么时候能跨过去。你信它会跨过去吗？

Christian： 百分之百信。我们在华尔街这里做财务关账的 agent，它现在已经能干活了，理解业务能到 90% 到 93% 的准确率。可你发布财报的时候，审计师会说，不好意思，这次你的数字高了 7%，这需要认证。关账要的是 100%，90% 不够。

Christian： 客户简报不一样。我在纽约跑客户拜访，会让 Joule 拼一份客户简报，90% 准确完全可以接受。我要最新财报，它给了上一季的，那又怎样？这种事本来要一屋子人准备，现在不用了。要不要 100%，取决于这个用例输了会怎样。

数据是脏的，先清理房子

Alex： 很多企业 pilot 做了一堆，真正进生产的很少，理由通常是数据基础太烂。AI 现在能自己把这件事搞定吗？

Christian： 它正在解决。一小时前我见了一个大客户，他说，我很喜欢你的关账助手，可它只有 93% 准确，而且公司里散着一百个财务系统，有些还不是 SAP 的。先把房子清理干净。你的数据一团糟，agent 的准确率自然往下掉。

Christian： 我们跟 Databricks、Snowflake、BigQuery 合作，零拷贝共享数据，再让 AI 去做匹配：SAP 对 Salesforce，Workday 对 SAP。语义层、本体（ontology）也在往外送。以后不需要一支数据科学家队伍，每个月去清财务、对 HR。

Alex： 本体是什么？

Christian： 举个例子。做资产管理时，agent 要读机器的传感器信号，判断它什么时候需要维护，再把工单和 SAP 数据对上：谁去修、备件在哪、原来的工人找不到就换谁。设备不能停机。这一整套逻辑拼起来，就是本体。

Alex： 所以一个纯粹的 API 连接，或者一个 MCP server，拿不到这些东西？

Christian： 对。模型是模型，业务上下文和治理是单独的一层。前沿模型只是一把钥匙，值钱的是它插进去的那把锁。

控制、合规、检查，会先被自动化

Alex： 我最近在想一个反方向的后果。《华尔街日报》有篇报道说，老板们在哀悼杂活的消失。让 AI 把报销自动化当然好，可如果剩下的全是高强度认知劳动，节奏又越来越快，这不像是个不会累的方案。

Christian： 财务、HR 里的各种控制，合规检查，这些典型工作会先被 agent 接走，那是几千人的全职工作。人腾出来的时间，会去做增值的事。

Christian： 我自己的例子。财报准备好，连讲稿都在，AI 甚至会告诉我什么时候提高音量、什么时候压低，我多出来的时间花在怎么把这场财报演讲讲好。

Alex： 我的媒体公司基本就我一个人跑，Claude Code 帮我做发票，很快还要做预测、盯收件箱。我很享受，但很少有降档的时刻。你手底下十万人，你听到的是什么？

Christian： 我没听到更累。我听到的是另一种问题：我的岗位还安全吗，会不会重组。我们现在的运转速度是满的，工作量并没有变少。AI 让人更有产出，不等于开发、财务、HR 就没有活了。

Alex： 大规模失业这个判断，我给不了。以前我会说肯定不会，现在只能说我不觉得会。公司手上的路线图太长，竞争对手又在动。选择只有两个：用更少的人加技术做同样的事，还是用同样的人加技术做更多的事。能活下来的公司会选后者。

Christian： 我跟我的人讲，12 个月后岗位构成会变。数据科学家、全栈开发要招更多，另一些岗位要的人会变少。问题在于你能重新训练多少人。有时候也需要新人进来，带着新技能、新心态，和有经验的同事配在一起，因为底层软件的领域知识还在别人脑子里。

Alex： 很多人不信再培训这套，觉得那是学者想出来的漂亮话。你那边真跑通过？

Christian： 跑通过。我们有一批写本地部署软件的开发者，转去写云软件，那是完全不同的活：要 devops，要自动测试，上线之后稳定性还是你的责任。这既是技能问题，也是心态问题。我们的 AI 同事 Joule 现在有八万人在用，刚开始也有抵触，慢慢训、慢慢带，看到活干得更快，这个坎就过去了。

SaaS 末日为什么没来

Alex： 过去大半年有个流行的说法：企业软件是给所有人造的，功能堆了一堆，你只会点其中几个。现在一句话就能生成软件，老牌软件会被 vibe code 出来的东西替掉。你当时什么反应？

Christian： 我的第一反应是，开发生产力在暴涨，别人为什么不能把我们 50 年建的东西复制一遍？然后我把产品经理叫来，一个一个过：哪些方案可能被轻松重写、替掉？答案是，ERP 里有 700 万个数据字段，要理解上亿条数据关联，还有按行业、按国家拆开的流程和本地要求。我们每年投几亿美元维持合规，这些不是提示词能补上的。也许有一两个小的、没有多少流程和数据上下文的产品会被复制，核心的 ERP、供应链、薪酬、财务不可能。

Christian： 当然我也不敢躺下，因为价值正在从系统记录层往上移到 agent 层。我们的 AI 必须世界级，否则连系统记录层的位置都守不住。

Alex： 我提一个更狠的版本。如果前沿实验室不再把最好的模型放在 API 上，自己去做你的活呢？我们见过没发布的模型组队跑 88 小时，解决最难的数学问题。他们完全可以说，这些模型不公开，但我们拿它去做 SAP 做了 50 年的业务。

Christian： 这个问题我几年前在 hyperscaler 身上也被问过。他们那么强，也可以说不给你基础设施了。但模型现在太多了，开源权重模型也做得很好，还要看价格和效果的比值。agent 干得好不好是一回事，干这件事花多少钱是另一回事。我不太担心某一家说我的模型不给你用了。

Alex： 那你会不会接受 OpenAI 或者 Anthropic 当你的前端？用户已经习惯打开 ChatGPT 了。亚马逊把 Meta 的 Muse 挡在门外，Shopify 说欢迎，你选哪边？

Christian： 两边都做。我们的做法是 Joule work：模型嵌进去，你可以切，在欧洲对主权有要求就用 Mistral 最新的，但界面是 SAP 的。三方 agent 也能通过 agent gateway 访问 SAP 数据，包括 OpenAI 和 Anthropic，前提是受控。主路由还是会走 Joule work，因为 API 和 MCP 给的上下文不够，本体、语义、治理都拿不到。做财务分析时，只有被授权看这些数字的人才会拿到报告，agent 得懂这件事。

我们公司也设了 token 限额

Alex： RAMP 的数据显示，8 月有 53% 的 AI 支出花在前沿模型上，到 9 月降到了 45%。企业开始发现自己不需要最好的模型。你们呢？

Christian： 一样的曲线。我们自己写代码还在大量用前沿模型，主权也有原因。但很多 agent，比如做一份人力报告、做一份财务报告，开源模型的效果就够好，比一下成本我们就切。现在我们很多 agent 用的已经是第五好的模型，我们一直在优化产出和 token 成本的比值。

Christian： 成本压力是最近才起来的。整体 token 支出在涨，但如果员工产出多 20%，成本涨了 30%，这笔账就不划算。我们要求产品经理：每个发到市场的 agent 都要拿不同模型测，一直测。

Alex： RAMP 还有一组数据，头部 1% 的员工消耗的 token 远超其他人。8 月这 1% 的人均月支出从 7976 美元降到 7250 美元，掉了 9.7%。你们内部那批 token 大户，你也让他们踩刹车了吗？

Christian： 我们也有那 1%。CFO 问我，这钱要花到哪去。说实话，我拖了一段时间才推 token 限额，因为前脚刚让所有人用 AI、去重新学习，后脚我自己就来设上限，这个信号不对。

Christian： 但到某个点，支出确实要管。我们三四个月前按岗位设了预算。做模型训练的那 1% 不设限，agent 的准确率靠他们。开发、产品经理、设计，还有财务和 HR，都有额度，够你把活干完，特殊任务可以找经理审批加额度。比限额更有效的是换模型，同一个任务换一个模型，成本能差 10 倍。

Christian： 我们还收购了一个做预测的表格 AI 模型。零售客户的 SAP 和非 SAP 数据放在一起，没有数据科学家建管线、做语义、清洗匹配，它做到了和十个数据科学家团队一样的准确率。所以前沿模型和开源模型之外，做预测的模型也在往前走。

Alex： 这对那些烧几十亿美元训前沿模型的实验室意味着什么？如果标准模型对很多客户已经够好，而前沿支出一个月掉 8%，这可能是个问题。

Christian： 这大概是每一家前沿实验室都在问自己的问题。唯一的出路是继续创新。你比其他人好得不够多，价格就撑不住。这个游戏大家都得玩。

换模型要一到两周，安全排在最前面

Alex： 从我们在前沿看到某种疯狂的能力，到它进入企业业务，要多久？

Christian： 新模型出来我们马上测。换模型一到两周，要改 API、调 MCP server，这些很快。多 agent 协作的 A2A 用例我们也在测。

Alex： 如果我是你，我最怕的是网络安全。你的客户手里是财务、供应链、销售、HR，一家公司最敏感的记录都在里面。一旦 agent 被拿去打零日漏洞，那才是灾难。

Christian： 所以这是最高优先级。我们用 AI 更早发现漏洞，主动去测公司和产品的防火墙，打补丁也在加快。安全预算也在涨，但发现漏洞本身就带来产出提升，涨得还算合理。

欧洲：管影响，别管技术

Alex： 欧洲给科技公司加了很多监管，美国这边的人说，去那边做生意不值得。你在欧洲最大的软件公司，你怎么看布鲁塞尔的动机？

Christian： 我相信动机是好的，没人想故意让欧洲吃亏。但离技术远的人，容易去管技术本身。要管它对社会的影响，管业务结果，别去管数据怎么用。现在他们有 omnibus，把简化和去监管的措施收在一起了，我很确定会有回滚。不止 SAP 在喊，很多创业公司、西门子这样的公司都在说：监管过头了。层层叠上去的 AI Act、Data Act，连法务和数据保护官都说不清。

留意一下 Klein 的口径：从 53% 掉到 45% 的，是花在前沿模型上的钱，不是模型能力本身在退。他真正在管的，是每一笔推理的成本换回来多少产出。

这一期最值得记的不是哪家模型排第几，是一个 CEO 把 AI 在企业里的时间表压到了几个月，同时给公司里的 token 上了限额。能力的问题，正在变成账目的问题。
