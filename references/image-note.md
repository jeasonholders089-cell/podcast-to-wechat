# 图文笔记（spec.json）

每期长文之外再出一套竖版图文笔记：封面看图、往下翻读判断，可以直接发小红书 / 视频号 / 公众号次条。
排版与出图由 `scripts/make_image_note.mjs` 做（HTML + Chrome 渲染），本文件是**写文案**的规范。

**每期必出**：每一篇公众号文章都要配一套图文笔记（`spec.json` + 9 张 PNG）和一份正文文案（`正文-<slug>-图文笔记.md`），不允许跳过。

## 分工

| 环节 | 谁做 | 产物 |
| --- | --- | --- |
| 图内文案 | 创作半程（agent） | `<期目录>\图文笔记\spec.json` |
| 正文文案 | 创作半程（agent） | `<期目录>\图文笔记\正文-<slug>-图文笔记.md`（配图一起发布的文案） |
| 出图 | `publish-episode.ps1` 调 `make_image_note.mjs` | `<期目录>\图文笔记\图文笔记-<n>-<名字>.png`（1080×1440） |

写完文案必须自检，退出码 0 才算过：

```
node C:\Users\Administrator\.codex\skills\podcast-to-wechat\scripts\make_image_note.mjs ^
  --spec D:\项目\AI内容生产\公众号产出\<slug>\图文笔记\spec.json --validate
```

此时插画还没出也不要紧：`--validate` 只查文案放不放得下，不查配图。

## 页面结构（8–10 页）

| 顺序 | `kind` | 这一页放什么 |
| --- | --- | --- |
| 1 | `cover` | 钩子标题。满幅插画，人物落在画面中央 |
| 2 | `lead` | 导语：这期讲什么、为什么值得看 |
| 3 | `figure` | 整幅插画（人物完整）+ 一行图注 |
| 4 | `points` | 主要观点，4–5 条编号要点 |
| 5… | `section` | 3–4 节正文，每节 `no`（01/02…）+ heading + 2–3 段 |
| 末 | `closing` | 收尾判断 + 一句留给读者的话 |

顺序不要打乱：图文笔记是靠「封面 → 导语 → 图 → 要点 → 正文 → 收尾」的节奏读下来的。

## 每页字数上限

脚本会按字宽自动缩字号（最小 26px）；缩到底还放不下就直接报错，不会把文字裁掉。所以按下面的量写：

| 字段 | 上限 |
| --- | --- |
| `cover.title` | 两行，每行 ≤10 字（`|` 断行） |
| `cover.subtitle` | ≤22 字（只排一行，超了会顶到插画） |
| `lead.paras` | 2 段，合计 ≤300 字 |
| `figure.caption` | 一句话 ≤40 字 |
| `points.items` | 4–5 条，每条 ≤60 字 |
| `section.paras` | 2–3 段，合计 ≤240 字；`closing` ≤26 字 |
| `closing.paras` | 2 段，合计 ≤200 字 |

## 写作规矩

- 只用文章里已有的观点、数字、人名。**不新增事实，也不替嘉宾补观点**
- 一句一个意思，短句；不用破折号 `——`，不写「首先 / 其次 / 综上所述」这类提纲腔
- 封面标题用判断句或反差数字，不要疑问句
- 数字要带代价感（金额、倍数、时长），不要当装饰
- 行内标记：`**词**` 朱红橙加粗（判断句）、`==词==` 朱红橙下划线（重点句），用在该强调的地方，一页合计最多两处
- **图内不写来源块**：图里不写「节目 / 嘉宾 / 发布 / 原视频」，也不写「详见公众号」；来源只留在文章里。导流只出现在正文文案的最后一行，见下一节
- 不用 emoji

## 正文文案（`正文-<slug>-图文笔记.md`）

这套图发出去时要配一段正文，和 PNG 一起交付。文件结构：

```markdown
# 图文笔记 · 正文文案

配图：`图文笔记-1-封面.png` 到 `图文笔记-<n>-<标题>.png`（1080×1440，共 N 张，按序号发布）

## 标题候选

1. …（3 条，陈述式判断为主）

## 正文

（从文章里压出的一条完整叙事，600–900 字，行内标记与图内一致）

完整全文可在公众号：粽子AI世界查看。

#话题1 #话题2 … #粽子AI世界
```

要求：

- **正文最后必须写清这一句**：`完整全文可在公众号：粽子AI世界查看。` 不能省，也不要改成语义模糊的版本，它是这套图文和公众号长文之间唯一的入口
- 导流只写这一句，不写「节目 / 嘉宾 / 发布 / 原视频」，来源仍然只留在文章里
- 正文只用文章里已有的观点、数字、人名，不新增事实
- 标题候选 3 条，句式规矩与推送标题一致

## 字段

必填：`name`（= slug，脚本按它找本期插画）、`title`、`kicker`、`pages`。
可选：`brand`（默认「粽子AI世界」）、`subtitle`、`coverArtTop`。

每页：`kind`、`out`（输出文件名，省略则按序号自动命名）、`heading`（`|` 断行）、`no`、`paras`、`items`、`closing`、`caption`、`art`（`portrait` / `square` / `wide`）、`artPos`（CSS `background-position`）、`artTop`、`artHeight`。

`art` 的 `wide` 指向横版封面，那张图本身就带标题文字，**不要用在图文笔记里**（只保留给排查用）。

版式默认值已经调好：封面用方版插画、整幅图页用竖版插画，都按 `center 100%` 下对齐裁切，人物完整且落在画面中央。
**除非该期插画构图特殊（人物被裁到），不要写 `art` / `artPos`。** 真被裁了就用 `artPos` 微调：`center 0%` 靠顶、`center 100%` 靠底。

## 骨架

```json
{
  "name": "<slug>",
  "kicker": "对话 XX CEO",
  "title": "他讲的这件事|**其实是这样**",
  "subtitle": "一句话说清这期凭什么值得看",
  "pages": [
    { "kind": "cover" },
    { "kind": "lead", "heading": "这期的钩子", "paras": ["…", "…"] },
    { "kind": "figure", "caption": "一句话图注" },
    { "kind": "points", "heading": "主要观点", "items": ["…", "…", "…", "…"] },
    { "kind": "section", "no": "01", "heading": "第一节的判断", "paras": ["…", "…"], "closing": "一句强调" },
    { "kind": "closing", "heading": "收尾判断", "paras": ["…"], "closing": "留给读者的一句话。" }
  ]
}
```

## 排查

| 现象 | 处理 |
| --- | --- |
| 报「正文放不下，超出约 Npx」 | 删减该页文字，或把一节拆成两页，重跑到 `--validate` 通过 |
| 报「封面 / 整幅图页没拿到配图」 | 本期插画文件名不是 `插画-<slug>-竖版.png` / `-方版.png`，或 spec 里的 `art` 写错了 |
| 渲染直接跳过 | 本期还没有插画（`-NoArt` 那轮）。插画出好后跑 `publish-episode.ps1 -Slug <slug> -ImageNoteOnly` 补上 |
| 人物被裁到 | 给该页加 `artPos` 微调 |
