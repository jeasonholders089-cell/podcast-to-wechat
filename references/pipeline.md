# pipeline.md · 细节规范

## §1 选题

- 时间窗：最近 7 天
- 方向：AI 赚钱 / AI 产品 / AI 创业 / AI 投资 / 认知 / 营销
- 形态：访谈类播客视频，20–90 分钟，英文一手优先
- 排序维度：热度、嘉宾权威性、观点密度、可提取性
- 硬条件：必须能取到**完整逐字稿**；只能拿到摘要片段的直接放弃
- 输出：`video_id` + 3 条选题理由（为什么值得做、差异化在哪、钩子是什么）

## §2 去重与持久化

- 读 `公众号产出\已发布-视频清单.json`，`items[].video_id` 命中就换一篇
- 无新片：只往 `automation-run.log` 写一行 `no-new-video`，本轮结束
- 成功后回写 JSON（UTF-8、不转义中文），字段：

```json
{
  "video_id": "…",
  "slug": "…",
  "title": "…",
  "source": "节目名",
  "published_at": "2026-09-28",
  "done_at": "2026-10-10T08:32:00+08:00",
  "draft_media_id": "…"
}
```

## §3 抓字幕

```bash
node scripts/fetch_transcript.mjs --video <video_id 或 URL> --out-dir <期目录>
```

- 走 TikHub（`TIKHUB_BASE_URL` + `TIKHUB_API_KEY`），一次调用同步返回全文
- 落盘 `full-transcript-<lang>.txt` 和 `video-meta.json`
- 来源四项（节目、嘉宾、发布、原视频）一律从 `video-meta.json` 抄，不要凭印象
- 抓不到就结束本轮，不拿半截稿写文章

## §3.1 写文章

体例：全文实录体对谈稿。

骨架：

1. 叙事钩子（1–2 段，从原片最有张力的一个事实/一句话切入）
2. `## 主要观点`（≤5 条，每条一句话）
3. 正文分节（`## 01 标题` …，逐轮问答）
4. 结尾判断（1–2 段，写清这期最值得记住的是什么）
5. `## 来源`（文末，排版成小字加灰）

**不写编译说明**（2026-10-16 起取消）。来源信息放文末，正文之前不要出现任何说明块或来源块 —— 开头直接进钩子，读者不用先读一段元信息才进正题。

**强调标记**：核心认知 / 判断句用 `**加粗**`（渲染成朱红橙加粗），重点语句用 `==下划线==`（渲染成朱红橙下划线）。一份稿子里两级强调都要有，但不要连续整段加粗。

### §3.1.1 回合整理（硬要求）

反面例子（原文里真实出现过，不许出现在成稿里）：

```
**主持人**：不。
**嘉宾**：说吧。
**主持人**：好。
```

要求：

- 主持人的短追问要扩成完整提问
- **每一轮主持人发言都必须以「？」结尾**：是提问就补问号；是背景陈述（「你提过…」「这也谈到这一点」）就在结尾补一个嘉宾真的回答了的问题。机检按 FAIL 级拦。
- 嘉宾的短答要并进前后论述
- 同一话题的连续短问答可以合并成一次完整问答
- 允许：补主语和连接词、顺成书面语、合并回合、删语气词
- **不允许：新增嘉宾没说过的观点和数据**
- 单轮发言正文 < 15 字，机检直接 FAIL

篇幅红线：正文有效字数不得低于逐字稿承载量的 1/3。低于就是写成摘要了。

## §3.2 去 AI 味 + 终检

先按 `anti-ai-rules.md` 改写，再跑：

```bash
node scripts/check_ai_flavor.mjs --md <文章.md> --transcript <逐字稿.txt>
```

FAIL 必须回改，直到 0 FAIL。WARN 可保留但要逐条判断。

## §4 排版

```bash
node <skill>\scripts\render_article.mjs \
  --in <文章.md> --out <文章.html> --template podcast-interview
```

渲染后检查 report：`html_img_tags = 0`、`html_external_links = 0`、`html_h1_tags = 0`。

## §5 标题与摘要

- 句式以**陈述式判断**为主（默认），疑问式只作调味：
  - 陈述式：`深度｜对话{机构或人物}：{一句反常识的判断}`（例：深度｜对话 Cal Newport：聊天机器人是个意外）
  - 数字式：`{具体数字}，{判断}`（例：一天 50 万亿 token，他说卖算力不赚钱）
  - 疑问式：只在冲突点非提问不可时用，**不许连用**
- 硬约束：
  - 给 ≥3 个候选，标注各自的句式和钩子；**候选里至少 2 个是陈述式**
  - 连续 10 期里疑问式 ≤3 期（约 1/3），且不允许连续两期都是疑问式
  - 标题必须带一个具体信息（数字 / 机构 / 名词 / 判断），不能只有情绪
- 展示用 ≤64 字；推送用 ≤32 字（超出用 `--title` 传短标题）
- 摘要 ≤120 字，写清「谁 + 说了什么反常识的话」

## §6 封面与配图

### §6.1 插画

出图由脚本做，agent 只提供两个字段（写在 `run-meta.json`）：

- `art_subject`：画面里的人和动作
- `art_motif`：背景抽象元素

```bash
node scripts/generate_art.mjs --name <slug> --out-dir <期目录> --subject "…" [--motif "…"]
```

提示词模板见 `assets/social-art-prompt.md`，`CRITICAL FACE REQUIREMENT` 段内嵌在脚本里，不允许手搓绕开。

- 竖版：3x4 用
- 方版：1x1 用，**单独出，不许裁竖版**
- 可用模型（降级链顺序）：`gpt-image-2` → `gpt-image-2.5-sunburst` → `gpt-image-2.5-flare`；`gpt-image-2.5` 实测 503，不要用

### §6.2 叠字出图

```bash
node scripts/make_social_cover.mjs --name <slug> \
  --title "第一行|第二行**高亮**" --kicker "对话 XX" \
  --stat "39 亿|融资额" --quote "金句" --art <插画.png> \
  --out-dir <期目录> --sizes 3x4,1x1,quote
```

标题里 `|` 断行、`**词**` 染橙。不给 `--art` 自动退回纯文字版。

### §6.3 出图后必做

1. `python scripts/check_art_faces.py <期目录>` —— 0 废图
2. 插画若重出，**必须重跑 §6.2 重合成两张贴图**
3. 贴图封面不进草稿箱

## §7 口播稿

- 3–4 分钟，800–1000 字；语速基准 250 字/分钟
- 落笔前先读 `assets/voice-dna.md`，按声纹写，不要套模板腔
- **一条主线**：症状 → 归因 → 解法 → 后果，每一段都在回答同一个问题；禁「观点一 / 观点二」并列铺开的提纲腔
- 第一人称推进：「我」必须是推进句子的主语，不能只当评价标签（「我觉得很妙」不算推进）
- 结尾一句独立成立的判断，必须能从前面的内容里长出来；不写提前备好的升华句
- 标注停顿（`／` 短停）与重音（`//` 重音或降速）
- 平台版本另存：抖音 60–90 秒（250–350 字，前 3 秒给反差或结论）`口播稿-<slug>-60s.md`；小红书 2–3 分钟偏「我挖到一个东西，分享给你」

## §8 视频切片

- 3–5 条，9:16 竖版，30–60 秒
- 每条写：标题、口播词、字幕要点、画面注记
- 成片交给剪映 / Descript，本环节只出文案

## §9 推草稿箱

```bash
node <skill>\scripts\push_to_wechat_draft.mjs --check
node ... --html <文章.html> --title "…" --digest "…" --cover <横版封面.png> --dry-run
node ... --html <文章.html> --title "…" --digest "…" --cover <横版封面.png>
```

只推：标题、摘要、正文 HTML、横版封面。
不推：口播稿、切片、逐字稿、贴图封面、图文笔记。

## §9.5 图文笔记

把长文再压成一套竖版图文（每页 1080×1440，8–10 页），发小红书 / 视频号 / 公众号次条用。
写作规范、页面结构、每页字数上限见 `references/image-note.md`。

分工：**文案**由创作半程写成两份，`<期目录>\图文笔记\spec.json`（图内文案，写完必须自检）和 `<期目录>\图文笔记\正文-<slug>-图文笔记.md`（配图发布的正文）；**出图**由 `publish-episode.ps1` 在推送之后调 `make_image_note.mjs` 完成。

```bash
# 文案自检（创作阶段，不需要插画）
node <skill>\scripts\make_image_note.mjs --spec <期目录>\图文笔记\spec.json --validate

# 单独出图 / 补出（改完文案后）
powershell -File <skill>\scripts\publish-episode.ps1 -Slug <slug> -ImageNoteOnly
```

**每期必出**：⑨ 不是可选项。`publish-episode.ps1` 在出图前检查三件事：`spec.json` 存在、`正文-<slug>-图文笔记.md` 存在、正文里有「完整全文可在公众号」这句导流；缺任何一项记 FAIL 并以 exit 7 结束本轮（已经完成的推送不回滚）。

三条硬约束：

1. 配图复用本期插画（封面用方版、整幅图页用竖版，`center 100%` 下对齐裁切），人物必须完整、落在画面中央。
2. 图文笔记的**图内**不写来源块：来源只留在文章里。
3. 正文文案（`正文-<slug>-图文笔记.md`）的最后一行必须写清导流：`完整全文可在公众号：粽子AI世界查看。`

## §10 每期目录

见 `SKILL.md` 的十环节表与本文各节的产物名。目录命名用公众号标题，与草稿箱标题保持一致。创作期先建英文小写短横线 slug，`publish-episode.ps1` 在完成后把目录改名为标题，并维护 `公众号产出\folder-map.json`；历史期重跑时 `-Slug <slug>` 会自动回落到映射目录。目录内的文件名仍沿用 slug（例如 `文章-<slug>.md`、`正文-<slug>-图文笔记.md`）。

图文笔记落在 `<期目录>\图文笔记\`：`spec.json` + `正文-<slug>-图文笔记.md` + `图文笔记-<n>-<名字>.png`。

## §0.6 合规与分发（P0，先于写稿）

规则原文与出处见 `references/platform-rules.md`。这一节只写**动作**，机检由 `check_platform_rules.mjs` 兜底。

### 0.6.1 编译稿一律不勾原创

《运营规范》3.6.1.5 明确把"未到独家授权的翻译、采访稿整理"排除在原创之外，违规的处罚是永久收回原创功能。所以：

- 纯编译期：**不勾原创**，靠来源四项、1 个合集、标题与摘要的关键词覆盖去换搜一搜收录。
- 评论版（每周 1–2 期可选）：自有论点 ≥40%、自有结构、补充事实核对后才可勾原创。

### 0.6.2 AI 声明写进来源块

`## 来源` 的最后一项固定加：

```
- AI 说明：本文由人工编译与校对，AI 辅助整理，封面与插画由 AI 生成。
```

推送后还要在后台编辑器里勾选"内容由 AI 生成"（接口没有这个字段，只能人工）。

### 0.6.3 标题与摘要

| 字段 | 硬要求 |
| --- | --- |
| `title` | ≤32 字，**22–30 字最佳**；前 15 字内出现主词（人名 / 机构 / 品类词） |
| `digest` | **100–120 字**；不填会被抓正文前 54 字，等于把摘要交给运气 |
| 禁用 | 震惊、速看、全网、沸腾、删前、重磅、内幕、史上最……（词表在 `lib/platform-rules.mjs`） |
| 涉企定性 | 标题出现"幻觉 / 骗局 / 崩盘"等词时，首段必须写明是受访者判断，不是本号结论 |

### 0.6.4 每期必须留的两条分发线索

1. `album`：本期归入的合集名，写进 `run-meta.json`。合集名本身就是搜索词，建议固定用一个，例如「AI 商业访谈」。
2. `note_title`：图文笔记推贴图时用的正标题，**≤20 字**，写进 `run-meta.json`。

### 0.6.5 节奏红线

- 自动跑批只到草稿箱，群发人工点。
- 用"仅发布"做长尾时**每天不超过 2 篇**；3.27 禁止脚本批量、连续发布，2026 年 4 月已有账号因此封号。
- 群发时间固定在工作日 20:00–22:30，不要每轮跑批都落在随机时段。
